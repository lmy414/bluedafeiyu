## 故障原因与修复

业务目录位于独立的 ext4 镜像文件系统。宿主盘仍有约 17 GiB 可用空间，但业务盘已用到 98%，只剩约 600 MiB。凌晨发布在预压缩阶段报 `ENOSPC`，之后的重试也没有成功切换线上版本。代码与内容已推送，因此 GitHub 清单领先于公开页面。

本次在线扩展了业务文件系统，镜像文件从 30 GB 增至 36 GB。发布后约有 6.4 GiB 可用空间。现有图片、数据库、历史版本和构建缓存均保留，服务无需停机。

预检与正式部署现在检查实际写入目录所在的文件系统，默认要求至少 2048 MiB 可用空间。配置项为 `BUILD_MIN_DISK_MB`。独立挂载盘的空间不足会提前报出具体目录及剩余容量。

执行器还存在重试误判：清单已经推送，但部署失败；下一次快照没有 Git 差异时，旧逻辑会跳过部署并回写成功。现在只有线上 `build-info.json` 的代码与图片仓提交均匹配时，才进入“无变更”流程。版本落后或构建记录缺失时继续部署。部署再次失败仍保留失败状态。

## 图片占位与首屏瀑布流补充修复

后续线上复测发现，桌面首页仍有约 0.15 的 CLS。侧栏状态已稳定，剩余偏移来自图片占位和瀑布流首次排列。部分历史作品的原图宽高为 0，CSS 中的 `aspect-ratio:auto` 又覆盖了浏览器的图片比例提示，懒加载图片在下载前会出现零高度。

补充修复从本地派生图读取真实尺寸，不改原图元数据。卡片、大图预览和漫画阅读页使用对应派生图的宽高；卡片 CSS 明确保留比例。网格组件在自身输出后同步执行最短列排列，后续模块继续处理追加、窗口变化和图片加载校准，避免等待模块下载后再重排整块首屏。

针对“部分预览图未加载”的反馈，检查了公开目录中 1382 件作品的预览图与大图地址。2764 个本地引用均存在且非空，1382 张预览图均能完整解码。已检查的浏览器首页图片及视频页 48 张封面加载成功。

Nginx 日志仍有图片 404，包括不存在的预览路径、旧路径及站内原图路径。当前发布清单没有引用这些失败路径；仅凭这些日志，不能确定它们就是用户看到的未加载图片。站内原图本来由图片仓 Raw 提供，不能直接按站内目录补造文件。

还需用具体页面或作品名称对照浏览器失败请求。后续应区分资源 404、CDN 或网络传输失败、懒加载未触发和图片已加载但布局不可见，避免用占位图掩盖原因。

## 是否改成 SSR

建议保留公开作品详情与资料页的静态输出。若要缩短发布等待、减少搜索和筛选的数据下载，可先试点少量按需渲染的路由。

SSR（Server-Side Rendering，服务端按请求渲染）的主要潜在收益是内容更新效率。当前页面已经在构建时生成完整 HTML，搜索引擎与无 JavaScript 浏览器都能读取正文。侧栏状态、控件增强和卡片重建造成的布局变化，仍需在浏览器端修复。

| 目标 | 静态站与本次修复 | 按需 SSR 的影响 |
| --- | --- | --- |
| 减少布局抖动 | 提前恢复状态，稳定占位，保留首屏节点 | 仍需相同的浏览器端措施 |
| 修复磁盘不足 | 扩容并检查目标文件系统 | 可减少部分 HTML 构建产物，但图片、原图仓和后台数据仍占空间 |
| 缩短内容上线等待 | 增量构建与预检产物复用 | 可把内容更新与整站页面生成分开，是主要收益 |
| 搜索、筛选与分页 | 当前需要下载本语言完整目录 | 可只返回当前结果页，分页 JSON 接口也能达到这一目的 |
| 首次响应时间 | Nginx 直接发送静态 HTML | 缓存未命中时增加计算和数据读取，需要实测 |
| 运维 | 当前公开前端无需 Node 常驻服务 | 需要适配器、运行进程、缓存失效、监控和回滚 |

本次修改公共布局，触发了完整构建。服务器预检耗时 711.62 秒，生成 1784 个路由产物、处理 7096 个语言页面；正式部署复用了预检结果，耗时 46.62 秒。较早的普通内容增量发布曾渲染 743 个路由、处理 2932 个语言页面，预检耗时 368.9 秒。这些记录说明发布等待确有改善空间，但不能用来推断 SSR 的请求延迟。

目前客户端目录也有可量化的成本。发布前本地构建含 1380 件作品，压缩后的中文目录为 412720 字节，英文为 808558 字节，日文为 798343 字节。按结果页返回数据可以减少访客下载量，无需先迁移所有详情页。

### 迁移前必须处理的代码约束

1. `frontend/src/lib/site.mjs` 与 `archive.mjs` 在模块初始化时读取快照并创建页面集合。常驻 SSR 进程需要按公开快照版本更新数据，避免进程启动后一直使用旧内容。
2. 四语言页面目前由 `localize-pages.mjs` 在构建后转换 HTML。按请求渲染需要将界面文案、作品译文、canonical、hreflang 和结构化数据统一接入渲染过程，不能只修改 `output` 配置。
3. 发布边界仍需保证只有已审核内容进入公开快照。应先校验图片、译文与公开字段，再原子切换快照；缓存键要包含语言、路径、筛选条件与快照版本。
4. 详情 URL、作品 ID、评论串、专题编排、sitemap 的正文更新时间和旧资源兼容方式继续保留。

### 建议的试点

先在隔离环境试点搜索页或搜索分页接口。这类页面已设置 noindex，适合比较按请求返回结果与当前客户端搜索的差异。复用现有组件，保持图片卡片的 HTML 和尺寸稳定。

试点要记录相同网络条件下的冷、热缓存 TTFB（Time to First Byte，首字节时间）、LCP（Largest Contentful Paint，最大内容绘制时间）、CLS（Cumulative Layout Shift，累计布局偏移）、每次搜索传输量、内存及并发请求表现，并验证服务失效时的回退方式。本次没有部署 SSR 原型，也没有 SSR 延迟或吞吐量测量，不能承诺改成 SSR 后会更快。

如果试点能稳定缩短内容生效时间，再考虑图库与新作品详情的按需渲染。Server Islands 会在浏览器中用动态片段替换占位内容，同样需要稳定尺寸，不能直接解决本次布局问题。
