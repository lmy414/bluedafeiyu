# 投稿署名

站内表单和 GitHub 投稿模板使用同一套署名规则。署名表示投稿者，与作品原作者、来源地址和授权状态独立。

## 投稿与展示

| 选择 | 必填信息 | 前端展示 |
| --- | --- | --- |
| 不署名 | 无 | 不公开投稿者名字、主页或 GitHub 用户名 |
| 署名 | 署名名字 | 显示名字 |
| 署名并填写主页 | 署名名字、有效主页地址 | 点击名字，在新标签页打开主页 |

个人主页链接可留空。填写时只接受 `http://` 或 `https://`，不接受带账号密码的地址。名字最多 120 字，主页地址最多 2048 字。

GitHub 表单无法按另一字段设置条件必填。模板会提示选择署名时填写名字，入站服务会校验；缺少名字的附件不会进入审核队列。GitHub Issue 本身的发帖账号仍公开可见。

## 字段与发布

投稿字段为 `credit`（`named` 或 `anonymous`）、`creditName` 和 `creditUrl`。队列保留这三个字段，审核同步和人工收录将它们写入作品的 `submitter`：

```json
{
  "submitter": {
    "credit": "named",
    "name": "小鱼",
    "url": "https://example.com/me",
    "github": ""
  }
}
```

不署名时，公开记录的 `name`、`url` 和 `github` 都为空。`origin.author` 表示来源作者，`origin.sourceUrl` 表示作品出处，署名流程不覆盖它们，也不会用来源链接代替主页。

老投稿没有 `credit` 字段，继续沿用已有作者展示。此次改动不批量修改已有作品，也不重算作品 ID 或 slug。

后台发布前需要运行 `20261004_000000_submitter_credit` 迁移，给 `works` 增加 `submitter_credit` 和 `submitter_url` 两列。发布顺序为后台迁移与更新、投稿服务更新、静态前台更新，避免新表单提交的署名被旧服务丢弃。
