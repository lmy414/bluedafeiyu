# 多语言内容维护

## 命名规则

英文站名固定为 DeepSeek Chan。DeepSeek 娘、鲸娘、鲸鱼娘和蓝色大肥鱼指向同一个角色，英文角色名也是 DeepSeek Chan。

其他英文角色用模型名加 Chan，例如 Claude Chan、GPT Chan、StepFun Chan。日文角色用模型名加“ちゃん”，例如 DeepSeekちゃん、Claudeちゃん。日文站名仍为 DeepSeek Chan。AI 产品本身保留官方模型名。

作者用户名、图片署名、URL、作品 ID 和 slug 保留原值。译文说明画面和梗的含义，不能补造作者、授权或官方关系。术语表见 `tools/localization/terminology.json`。

## 内容和发布

作品英文、日文分别包含 `name`、`description`、`commentary`、`tags`、`seoTitle`、`seoDescription`、`faq`、`originNote`、`licenseNote`。每种语言的 FAQ 有两组作品专属问答。标签与中文保持相同数量和顺序，检索链接继续使用原标签。

存量译文在 `data/work-localizations.json`，以冻结的作品 ID 为键。新投稿在审核结果的 `content.i18n` 中保存译文，后台导出时写入作品清单。后台补全把最终译文存入 `legacyData.i18n`，处理草稿保存在任务 JSON。`submissions.agent_progress` 只镜像处理进度。

`sourceHash` 绑定中文标题、说明、点评、标签、角色、分类及来源和授权备注。中文内容修改后，旧译文失效。构建检查全部公开作品的英日内容，缺失或过期时停止发布，避免发布中文正文的英文页面。

完整构建还会调用 `tools/localization/audit-pages.mjs` 扫描英日正文、标题、图片说明、SEO 元数据和结构化数据。发现中文回退或错误角色名时停止发布。报告保存在源码仓库的 `.build/native-localization-audit.json`，不加入公开发布包。单独运行检查仍可指定构建目录和可选的报告路径。

公共界面的固定正文与 FAQ 保存在 `data/site-copy-localizations.json`。角色页和分类页的动态介绍由 `frontend/scripts/native-archives.mjs` 使用英日模板生成，作品示例、常见标签和数量读取当前快照的真实译文，不依赖旧中文整句匹配。独立语言 URL、canonical 和 hreflang 沿用现有构建流程。页面 HTML、结构化数据、卡片、搜索和预览读取同一份译文。

## 使用 PI 回填

先运行站点的数据暂存和快照命令，确认 `dist/site-data.json` 是最新公开数据。再运行：

```powershell
node tools/localization/pi-backfill.mjs --batch-size 8 --concurrency 8
```

脚本调用本机 PI 已配置的 `cpa` 提供方及 `deepseek/deepseek-v4.1-flash`。私有配置和凭据留在 PI，脚本不复制密钥。其他机器通过 `--pi-cli` 指定 PI 入口。

脚本按 `sourceHash` 续跑，输出到 `.build/work-localizations.generated.json`。每批输入、输出和实际模型用量留在 `.build/localization-runs/`。失败批次重试三次，仍失败则返回非零状态。审核译文及覆盖数后，将结果保存为 `data/work-localizations.json`，再完整构建并验收英日页面。

`node tools/localization/pi-site-copy.mjs --site-dir .build/site` 从已有构建的中文页面抽取公共文案，交给同一个 PI 模型本地化。修改页面模板后，应更新公共文案并检查未翻译文本。不要手工修改发布目录里的 HTML。

## 后台 AI 任务

自动审核、补全和翻译由 Hermes Agent 原生工具处理，规范在 `ops/hermes/editorial-skill/SKILL.md`。业务服务不请求独立模型。完成前仍要求完整 `i18n.en` 和 `i18n.ja`；历史 v1 记录保持可读。缺译文或字段校验失败时保留草稿，等待 Agent 修正，不转人工。

投稿队列的私有摘要和 AI 记录必须完整保留通过校验的 `content.i18n`，重启后也不能丢失。修改审核内容契约时同步检查 `server/queue.mjs` 的保存白名单。修复前已入库的缺失译文可通过后台 AI 补全接口指定 `fields: ["i18n"]` 回填，核验 `sourceHash` 后再发布。

同步审核内容到后台时，分类关系必须沿用 `content.categoryIds` 的顺序。不能按分类查询结果的顺序重新排列，否则同一内容的 `sourceHash` 会变化，已生成的译文会失效。

后台 AI 补全返回持久化任务编号。Agent 通过工具保存中文和单语言草稿，全部语言通过校验后完成任务。单条建议仍由站长核验后保存；批量任务按已确认范围写入。生成期间作品有并发修改时，工具返回 409，要求重新提交。

修改前端或服务端后，按仓库既有 Git 发布流程上线。修改后台代码时，还需构建并部署对应的 Admin Release。上线后检查公开英日详情页，以及审核任务使用的代码版本。

## 署名与授权申请

Hermes 申请工具只更正作者、来源 URL 或照录的授权备注。作者和 URL 保留原值，授权类型保留存量值。授权备注变化后重新校验 sourceHash，分别保存 en 和 ja；原有标题、点评、标签及 FAQ 保持原译文。公开清单与四种语言页面验证通过后，执行器才回复并关闭 Issue。详见 [Hermes 审核与发布接线](Hermes审核与发布接线.md)。
