# 抓取与更新时间

## sitemap 日期

`frontend/scripts/sitemap-history.mjs` 比较新旧页面的正文、SEO 元数据和结构化数据。内容相同就沿用上一版 sitemap 的 `lastmod`。正文、FAQ、作者信息、图片说明或链接变化时，使用本次构建时间。每种语言分别比较，英日译文变化只更新受影响的页面。

浏览量、下载量、外部评论、页脚版权年份、CSS 类和脚本版本不参与比较。sitemap 保留四种语言的 URL 与 hreflang，不输出 Google 忽略的 `priority` 和 `changefreq`。

首次接入时，旧 sitemap 没有日期。构建采用现行发布版本的 HTML 文件修改时间建立基准，不反推作品最早修改时间。此后以内容比较结果维护日期。这个初始基准无法还原接入前每一次内容修改。

历史直接来自上一版发布目录中的 sitemap 和 HTML，无需新增数据库或单独的可写历史文件。服务器发布时，`SITE_PREVIOUS_DIR` 指向 `current`。本地默认读取待覆盖的输出目录，也可以用该环境变量指定已有构建。构建失败不切换线上版本；回滚后，下次发布从回滚版本继续比较。

历史日期无效、日期在未来或 sitemap 对应页面缺失时，构建停止，保留现行发布版本。

## 公开资源和后台

`robots.txt` 允许公开 JSON、图片、JS 和 CSS。公开作品快照使用 `/site-data.json`，不新建 `/data.json`，也不把 JSON 加进 sitemap。首批图片位于 `/data/blue-fish/previews/`，这个目录必须允许抓取。

robots 限制 `/admin`、`/cms-api` 和 `/api/v1/internal/`。登录页 `/admin/login` 单独允许抓取，让 Google 能读取 `noindex`。后台登录与 API 继续使用原有鉴权。后台 nginx 片段返回 `X-Robots-Tag: noindex, nofollow`，登录页也保留原有 robots 元标签。

robots 管理抓取，不代替鉴权，也不保证移除已收录的 URL。如果后台地址已被收录，先允许爬虫读取 `noindex`，确认移出索引后，再限制抓取。其他公开资源继续可访问。

## 原作者

图片 `creator` 只读取可靠的 `origin.author`，投稿署名仍作为 `creditText`。未知原作者保持缺省。补录实际原作者后，下次发布自动输出 `creator`，对应页面的内容比较也会更新 `lastmod`。

`creator` 是 Google 图片元数据的推荐字段。未知作者的推荐项提示会保留，不用站名或投稿者姓名填充。

## 验证

前端测试覆盖重复构建、单语言修改、新增或下架 URL、统计与样式变化、无效历史及 robots 规则。发布后检查 sitemap 的日期和 hreflang、公开快照与图片的 HTTP 状态，以及后台响应头和鉴权。

Google 官方依据：[sitemap 日期](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)、[图片元数据](https://developers.google.com/search/docs/appearance/structured-data/image-license-metadata)、[robots](https://developers.google.com/search/docs/crawling-indexing/robots/intro) 和 [noindex](https://developers.google.com/search/docs/crawling-indexing/block-indexing)。
