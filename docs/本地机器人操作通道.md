# 本地机器人操作通道

## 配置设备

本地机器人使用独立的站长账号，角色为 `owner`。上传作品、人工收录、编辑、专题选图、封面排序、发布、隐藏、删除和成员管理均复用站长权限。每台设备可单独停用或轮换密钥，审计记录保留设备名称。

打开后台“设置 → 本地机器人”，填写设备名称并创建身份。密钥只在创建或轮换时显示一次。将配置保存到当前用户的 `~/.config/dafeiyu-admin/device.json`：

```json
{
  "baseUrl": "https://xn--pssy23gqgbz2d718b.com",
  "apiKey": "填写设备密钥"
}
```

配置包含站长凭证，应只允许当前用户读取。凭证不写入仓库或日志。`--config <文件>` 或环境变量 `DAFEIYU_ADMIN_CONFIG` 可指定其他配置文件。

客户端需要 Node.js 22 或更新版本，无需安装额外依赖。从站点仓运行：

```powershell
node tools/admin-client.mjs me
node tools/admin-client.mjs tasks --status running
node tools/admin-client.mjs publish-plan
```

## 上传与人工收录

将参数保存成 UTF-8 JSON 文件，例如 `upload.json`：

```json
{
  "file": "E:/作品/新作品.png",
  "name": "作品名称",
  "character": "deepseek",
  "categoryId": "meme",
  "origin": { "author": "作者名称", "sourceUrl": "https://example.com/work" },
  "include": true
}
```

```powershell
node tools/admin-client.mjs upload --input upload.json
# 简单上传也可直接传参数
node tools/admin-client.mjs upload --file "E:/作品/新作品.png" --character deepseek --category-id meme --include
```

角色和类型使用站点词表 ID。图片上限为 16 MiB，支持格式以投稿服务校验为准。`include:true` 表示站长已确认收录。系统保存私有原图、同步预览，再创建一条持久任务，依次补齐缺失中文、生成英日译文、校验原图，最后进入待发布。已有人工文案和有效译文会保留。

`include:false` 或省略时只上传，等待看图审核。同图重复上传复用原记录。收录请求可提供固定的 UUID `requestId`，网络重试时复用此值，防止重复排队。

已有投稿可用 `include` 操作收录，参数为 `{ "ids": ["sub_xxx"] }`。`tasks` 返回统一状态、步骤、错误和任务编号。用 `{ "task": "任务编号" }` 查询单条任务。

```powershell
node tools/admin-client.mjs tasks --input task.json
node tools/admin-client.mjs retry --input retry.json
```

`retry.json` 内容为 `{ "jobId": "任务编号" }`。重试保留已完成的语言草稿。取消用 `cancel`，已完成的写入继续保留。任务存放在服务器，关闭本地进程不影响处理。

## 创建专题

将精选作品的稳定 ID 按展示顺序写入 `workIds`，封面须属于这些作品。例如 `topic.json`：

```json
{
  "topicId": "my-collection",
  "name": "我的精选",
  "summary": "专题说明",
  "nameEn": "My collection",
  "summaryEn": "Selected works.",
  "nameJa": "作品集",
  "summaryJa": "選んだ作品です。",
  "status": "draft",
  "order": 10,
  "workIds": ["sticker_example_a", "sticker_example_b"],
  "coverWorkId": "sticker_example_a"
}
```

```powershell
node tools/admin-client.mjs topic --input topic.json
```

客户端按 `topicId` 创建或更新专题，解析作品 ID 后调用原生站长 REST API。省略 `workIds` 会保留原有成员；传空数组会清空成员。确认内容后将 `status` 改为 `active`，再检查发布计划。成员必须由调用者明确选择。

## 发布与其他操作

```powershell
node tools/admin-client.mjs publish-plan
node tools/admin-client.mjs publish --input publish.json
```

`publish.json` 内容为 `{ "confirm": true }`。发布请求复用现有执行器，执行原图校验、导出、Git 提交、构建、原子切换和结果回写。接口返回任务编号后，在任务中心查看最终结果。

`request` 提供完整站长 REST API 调用，参数包含 `method`、`path` 和可选 `body`。例如查询作品：

```json
{ "method": "GET", "path": "/cms-api/works?limit=10&depth=0" }
```

客户端只向配置的同一站点发送凭证，只访问 `/cms-api/`，拒绝重定向。服务器继续执行原有字段、权限和发布校验。

## 维护与验证

原有 `bot` 服务身份继续遵守原来的限制。本地机器人获得站长权限，依靠独立账号和审计区分操作者。停用设备 API Key 后，该密钥立即失效。

自动化覆盖原生 API Key 认证、站长专题关联、审计脱敏、上传鉴权与去重、翻译中断续做、取消和重复请求。服务器引导脚本为发布包内的 `provision-device.mjs`，仅在拥有服务器管理权限时使用。脚本从环境变量读取数据库与设备名称，默认拒绝覆盖已有设备；轮换须显式传 `--rotate`。
