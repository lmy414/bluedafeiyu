## 独立 URL 的准确含义与专题目标

当前首页 `/`、分类目录 `/category.html`、专题目录 `/topics.html`、投稿 `/submit.html`、关于 `/about.html`、推荐 `/projects.html`、更新日志 `/changelog.html`，以及每件作品 `/works/<slug>.html`，都有独立的可请求页面地址。`/index.html` 也是首页的可访问地址，但其 canonical 指向 `/`。分类筛选的 `#c=`/`#s=`/`#q=`（包括当前四个内容分类）、专题当前的 `#t=`、站内搜索状态与页面内锚点，只是同一 HTML 后的片段，不算各自独立的可收录页面。404 是错误响应，不应加入 sitemap。

**用户已确认：每个专题都需要单独收录和专属展示页。** 目前权威 `data/topics.json` 为 `[]`，没有现存专题需要搬迁。应在第一个专题上线前完成以下项目：

- 仍由站长维护 `data/topics.json`，只为快照里 `active` 且有有效 `workIds` 的专题生成页面。建议固定 `/topics/<id>.html`，沿用已定义的稳定 `id`，发布后不随名称变化；`id` 唯一性和路径安全需要在生成阶段校验。
- 每个页面输出静态 HTML：专题名称、简介、封面、作品卡片 `<a href="../works/<slug>.html">`、返回专题目录的入口；首批主要内容不用依赖点击、搜索或脚本执行才出现。专属 `<title>`、`meta description`、H1、canonical 和社交分享元数据应与实际页面内容一致。
- `/topics.html` 保留作目录，但目录卡片须链接到各自独立 URL；`/topics.html` 本身继续存在。专题页加入 `sitemap.xml`；发布构建校验页面数、存在性、作品链接及不存在专题时的零页面行为。下架专题要决定返回 404、重定向还是保留历史页，不能留下“200 空壳”。
- 不把 `#t=` 当成新专题页的 canonical；可在确认兼容需求后，保留旧 hash 跳转到新地址。由于尚无专题，上线前没有历史专题 URL 必须迁移。新 URL 结构是产品需求，并非谷歌强制使用的目录命名。
- 先用首个真实专题或测试夹具验收生成器、链接、移动端、三语页面文本、结构化数据（若采用）和 sitemap。Google 最终是否收录仍需上线后用 Search Console 核对，不能通过代码保证。
## 内容分类独立页面（用户已确认）

这里的“分类”指 `data/categories.json` 中的内容分类，不把 `data/characters.json` 的角色也自动当成内容分类。当前四个启用分类是 `meme`（梗图）、`illustration`（插画）、`setting`（设定图）和 `comic`（漫画）；它们现在仅通过 `/category.html#s=<id>` 筛选，**没有独立分类展示页**。用户要求：每个上线分类都有自己的可访问、可收录页面；新增一个启用分类即自动生成一个新页面，维护者不应手工复制模板。

- 建议公开地址 `/categories/<id>.html`（区别于现有 `/category.html` 目录），`id` 是稳定路径键；改名称不自动改 URL。先检查 `id` 非空、唯一、路径安全，再允许进入构建。四个现有分类也要补齐独立页，而不是只对新分类生效。
- 从 `data/categories.json` 和已归一的 `site-data.json` 自动生成；页面输出分类名称、说明、匹配的**已发布**作品及其链接，并有独立 title、description、H1、canonical。不要为了有页而创造不存在的作品或文案。
- `/category.html` 继续作为所有分类及角色的总入口。分类选项与相关作品卡片应能到达新的分类 URL；`/category.html` 和已有 `#s=` 分享链接仍能正常筛选，角色/关键词/组合筛选保持可用。对单纯 `#s=<id>` 是否做前端跳转可后续决定，不强制迁移旧分享链接。
- 只有 `status: active` 的分类进入站点地图。**空分类页面是否可索引尚需明确发布规则**：建议可生成供用户导航，但若没有任何已发布作品，不进入 sitemap，按实际页面内容决定 `noindex` 或延后公开；不要输出大量“200 但无内容”的分类薄页。上线前应以一个空分类夹具核对这条规则。
- 构建与测试必须断言：启用分类与生成页面一一对应、每页 canonical/标题/链接正确、新增清单项后无需手写 HTML 即产生页面、停用分类不继续公开；对停用后原 URL 的 404/重定向策略单独验收。
- 角色筛选 `#c=` 是否也升级成每个角色的独立展示页，本条需求未覆盖。先保持现状，不臆造角色页规则。
## 现有链接保护与改址预案（用户已确认）

**本次优先方案：不改任何已发布页面的公开 URL。** 源码可按板块移动，但构建后的 `/`、`/index.html`、`/category.html`、`/topics.html`、`/submit.html`、`/about.html`、`/projects.html`、`/changelog.html`、`/works/<slug>.html`，以及图片、脚本、样式、站点地图等正在使用的资源路径应保持可访问。作品 `id` 和 `slug` 不重算。新分类 `/categories/<id>.html`、新专题 `/topics/<id>.html` 是**新增地址**，不替换目录页和作品页；具体新地址需在实现前固定，避免上线后再次变更。

现有分类和专题分享链接的 `#s=`、`#t=` 属于 URL 片段，浏览器不会把片段发送给服务器。因此无法通过服务器为每个片段做定向 301/308。`/category.html#s=meme` 应先继续按原功能工作；目前没有已发布专题，若发现外部使用了 `/topics.html#t=<id>`，需保留页面内兼容逻辑或用前端跳转到对应的新专题地址。前端跳转主要保护老用户访问，不等同于服务器端永久重定向的 SEO 信号。新链接上线后，站内导航和 sitemap 应直接使用新分类/专题的规范 URL，不继续制造新的 hash 详情入口。

如果**以后确实必须更改已发布 URL**，不能仅移动文件或改 canonical；先做一张逐项映射表（旧 URL → 内容最匹配的新 URL），核对 Search Console、sitemap、内部链接和图片等资源入口，再一次落实下列措施：

1. 在服务器配置**逐页 301 或 308 永久重定向**到最终地址，不使用与旧页无关的首页作为兜底；避免重定向链与循环。
2. 新页返回 200，内容与原页对应，使用指向自身的绝对 canonical；站内链接和 sitemap 只放最终规范 URL，检查 robots/noindex 不拦截新页。旧页重定向比仅在旧 HTML 中写 canonical 更适合真正弃用旧 URL 的情况。
3. 旧地址的重定向至少保留一年；用户角度可长期保留。逐条测试旧 URL 的跳转终点、新页资源和 404，并在 Search Console 监控新旧 URL 索引、展示与抓取错误。短期波动仍可能发生，**没有保证排名完全不受影响的方法**。
4. 仅同一域名内改路径时，不需要 Search Console 的“地址更改”工具；该工具用于域名或子域名迁移。若只是移动源码而公开 URL 不变，上述改址流程不触发，但仍须验收所有旧地址可访问。

Google 官方参考：[SEO 入门指南的“不突然推翻现有结构”](https://developers.google.com/search/docs/fundamentals/seo-starter-guide#organize)、[网站迁移（网址变化）](https://developers.google.com/search/docs/crawling-indexing/site-move-with-url-changes)、[规范网址与信号强度](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)。

## 构建和引用关系

当前构建顺序由 `tools/build_site.mjs` 固定：

1. `tools/stage_data.mjs`：`data/` → `dist/` 对应清单。
2. `tools/sync_content.mjs`：内容仓图片及 Issue 模板 → `dist/` 暂存。
3. `tools/build_site_snapshot.mjs`：生成 `site-data.json` 和 `site-data.js`。
4. `tools/generate_work_pages.mjs`：生成作品详情页。
5. `tools/generate_sitemap.mjs`：生成索引。
6. `tools/build.mjs`：复制到 `.build/site/`，校验必需文件并排除构建专用目录。

`tools/build.mjs` 的 `REQUIRED_FILES` 写死了根目录页面、样式、脚本、清单等发布路径。`tools/generate_sitemap.mjs` 写死静态页面 URL；详情页生成器写有 `../` 资源与导航路径。若移动**源码**，必须让构建映射到完全相同的旧发布路径；不要把这些公开路径当作源码目录同时移动。现有网址的保留是这次前端整理的硬约束。首页、分类、专题和作品详情之间还互相使用 `#c=`、`#q=`、`#t=` 链接。页面资源的相对路径、404 的根路径、canonical、站点地图和资源版本号也要逐项复核。
