# 图片替代文本

公开页面的每个 `img` 都必须显式声明 `alt`。不要为了通过扫描而把所有空值填成文件名、关键词列表或猜测的画面描述。

- 作品卡、详情和预览使用 `frontend/public/components/image-alt.js` 的 `workImageAlt`，输入当前语言的真实作品名称与编辑描述。描述已包含名称时不重复添加；共用描述的作品以各自标题区分。没有逐图确认的视觉细节不得编写成事实。
- 独立视频封面链接使用视频标题作为 alt，链接内的播放文案提供功能说明。英日版本采用 `data/video-archive.json` 中的译文，繁体版本在构建期转换。
- 合集拼图、同一链接里已有标题的缩略图、紧邻作者名的头像、隐藏的装饰叠图保留 `alt=""`，避免重复朗读。独立图片链接不能仅因页面其他位置有标题就视为装饰。
- 二维码、品牌入口和分享图使用已有的功能或品牌名称。保留作者署名，不对署名做角色名替换或繁简转换。

静态 HTML 已标记为完成翻译，浏览器不会再次翻译整页。新内容图必须同时检查 `frontend/scripts/native-content.mjs` 的构建期处理和动态组件的 `SiteLang.localWork` 输入，不能只在运行时等待 OpenCC 修复静态文本。

完整构建后运行：

```bash
npm --prefix frontend run check:image-alt
npm --prefix frontend test
```

检查其他输出目录：

```bash
node frontend/scripts/audit-image-alt.mjs <构建目录>
```

审计按四语言报告 HTML 页数、图片出现次数、缺失属性、空文本和非空文本，包括惰性 feed 的 template 与 noscript；次数不是唯一图片文件数。缺少属性或主要内容图为空会使命令失败。空 alt 的合理性仍需按上下文审查；工具不判断画面与文字的语义一致性，也不审查跨域评论 iframe。

修改后在真实浏览器抽查首页、角色、详情、视频、合集、连载与社群页，覆盖四语言及预览、切图、放大和加载更多。第三方原图失效、内容仓缺图与替代文本是不同问题，需分别记录。
