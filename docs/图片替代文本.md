# 图片替代文本

公开页面的每个 `img` 都必须显式声明 `alt`。不要为了通过扫描而把所有空值填成文件名、关键词列表或猜测的画面描述。

- 作品卡、详情和预览使用 `frontend/public/components/image-alt.js` 的 `workImageAlt`，输入当前语言的真实作品名称与编辑描述。描述已包含名称时不重复添加；共用描述的作品以各自标题区分。没有逐图确认的视觉细节不得编写成事实。
- 独立视频封面链接使用视频标题作为 alt，链接内的播放文案提供功能说明。英日版本采用 `data/video-archive.json` 中的译文，繁体版本在构建期转换。
- 合集拼图、同一链接里已有标题的缩略图、紧邻作者名的头像、隐藏的装饰叠图保留 `alt=""`，避免重复朗读。独立图片链接不能仅因页面其他位置有标题就视为装饰。
- 二维码、品牌入口和分享图使用已有的功能或品牌名称。保留作者署名，不对署名做角色名替换或繁简转换。

静态 HTML 已标记为完成翻译，浏览器不会再次翻译整页。新内容图必须同时检查 `frontend/scripts/native-content.mjs` 的构建期处理和动态组件的 `SiteLang.localWork` 输入，不能只在运行时等待 OpenCC 修复静态文本。

完整构建后运行：

```bash
npm --prefix frontend run check:image-alt
npm --prefix frontend test
```

检查其他输出目录：

```bash
node frontend/scripts/audit-image-alt.mjs <构建目录>
```

审计按四语言报告 HTML 页数、图片出现次数、缺失属性、空文本和非空文本，包括惰性 feed 的 template 与 noscript；次数不是唯一图片文件数。缺少属性、主要内容图为空、独立图片控件无名称，或空值不在经过审查的白名单内，都会使命令失败。预览、放大、角色及专题正文图同样纳入内容图规则；白名单不能覆盖内容图规则（无作品角色的站点图标占位除外）。空 alt 的合理性仍需按上下文审查；工具不判断画面与文字的语义一致性，也不审查跨域评论 iframe。

修改后在真实浏览器抽查首页、角色、详情、视频、合集、连载与社群页，覆盖四语言及预览、切图、放大和加载更多。第三方原图失效、内容仓缺图与替代文本是不同问题，需分别记录。


## 空值白名单与动态验收

审计输出 `decorations` 分类计数；分类之和必须等于全部空 alt 数。未知空图不会自动认定为装饰。规则保存在 `audit-image-alt.mjs` 的 `decorativeReason`：

| 允许空值的组件 | 必须同时满足的条件 |
| --- | --- |
| 合集拼图、创作者作品预览、首页入口/精选拼图、连载封面 | 同一链接内部有对应标题；仅有通用操作文字不足以放行 |
| 视频作者头像、专题作者头像、作者档案头像 | 对应作者名存在；头像若在独立链接内，该链接还须有名称 |
| 作者图标链接 | 隐藏的头像位于有名称的作者入口/推荐链接内 |
| 活动重复封面 | 限指定重复组件，同时 `aria-hidden="true"` 与 `tabindex="-1"` |
| 无作品角色占位 | 仅 `/avatar.png`、无 cutout、无封面作品署名链接 |

显式内容图（含 `.preview-photo`、`.preview-zoom`、角色封面）即使在有标题的拼图中也不能为空。其他独立图片链接/按钮若无可访问名称，报告 `empty-image-control`；其他未审查空值报告 `unreviewed-empty`。这是保守的组件策略，不是完整的浏览器可访问名称算法。

运行可复现的真实浏览器检查（需要环境已有 Playwright 和 Chromium）：

```bash
node frontend/scripts/check-image-alt-browser.mjs http://127.0.0.1:5173 /tmp/image-alt-browser.json
```

可用 `PLAYWRIGHT_MODULE` 指定已有 Playwright 模块，`CHROMIUM_EXECUTABLE` 指定浏览器路径。检查访问真实本地站点和其动态目录，按简体、繁体、英文、日文打开首页预览、下一张、详情放大及 GPT 角色页，使用真实快照及其译文逐字断言 alt；同时将每个交互状态的 DOM 交给同一审计器。报告记录语言、路径、作品 slug、真实标题、alt、装饰分类及问题，而非仅依赖英文 fixture。
