原先 `Archive.astro` 将图库、视频和分类页排除在 `refined` 主题之外，导致这些页面沿用旧配色、导航尺寸和控件样式；兼容 CSS 中也保留了另一套明暗颜色变量。

- 所有公开页面统一使用同一外壳和主题。颜色集中在 `ArchiveTheme.css`，旧变量映射到同一套语义颜色。
- 列表、说明文档和投稿页共用 `PageHeading`。说明页统一为“标题与简介 → 分区导航 → 正文”。首页和作品、角色详情保留各自的内容结构。

## 本地 Codex 执行步骤

1. 阅读仓库 `AGENTS.md` 和本文，保留本地未提交工作。拉取 `origin/main`，确认其中包含“fix: 统一公开前端主题与共享组件”提交，并记录要发布的完整 SHA。不要覆盖用户自己的修改。
2. 使用本地已有的服务器连接与部署配置，确认 `SOURCE_DIR`、`CONTENT_DIR`、`DEPLOY_ENV`、`DEPLOY_ROOT` 和现行 `current`，记录旧 release 以便回滚。凭据与服务器私有路径不要写回仓库。
3. 按仓库要求在服务器从 GitHub 拉取源码和内容。运行 `ops/deploy-server.sh` 的独立副本；不要直接执行随后会被 `reset --hard` 替换的工作树内脚本，也不要上传云端或本地构建目录。
4. 此次公共主题影响所有页面，建议本次使用 `BUILD_FULL=1` 做一次完整发布。保留增量缓存，不通过删除缓存解决问题。部署脚本负责构建、预压缩、原子切换与健康检查失败回滚。
5. 发布成功后核对公开 `build-info.json` 的 `sourceCommit` 与服务器实际发布 SHA，并确认页面带有 `data-design-version="20261025-1"`。若主分支已有更新，确认该 SHA 包含本次前端提交。

服务器端执行示例（先从现有配置确定 `SOURCE_DIR` 和 `DEPLOY_ENV`）：

```bash
git -C "$SOURCE_DIR" fetch origin main
git -C "$SOURCE_DIR" rev-parse origin/main
deploy_copy="$(mktemp /tmp/bluedafeiyu-deploy.XXXXXX.sh)"
git -C "$SOURCE_DIR" show origin/main:ops/deploy-server.sh > "$deploy_copy"
BUILD_FULL=1 DEPLOY_ENV="$DEPLOY_ENV" bash "$deploy_copy"
```

不另外上传图片，也不改人工精选专题成员；如果主分支出现了新的内容发布，按 `AGENTS.md` 核对其 `shared/data` 同步要求。

## 上线验收与回滚

- 检查首页、图库、一个图片分类、视频、角色、合集、创作者、社群、友链、关于、更新日志和投稿页。确认导航外壳、背景、按钮与标题层级一致。
- 检查 320px、390px、768px 和桌面宽度。确认没有整页横向溢出；图库筛选器、视频排序栏和投稿标签正常排列。
- 切换明暗主题及简体、繁体、英语、日语。检查文案、对比度、语言链接、当前导航状态和页内锚点。
- 操作图片筛选、视频排序、导航收起/展开、图片预览、收藏及投稿方式切换。不要为了验收提交真实投稿或作者登记。
- 抽查作品详情、图片加载、下载入口、版权说明及浏览/下载统计接口。静态预览不提供线上统计服务，生产环境需要单独检查。
- 检查部署日志、健康检查和 CSS/JS 请求；若 CDN 仍缓存旧 HTML，只按现有运维规则刷新相关页面，不清理历史发布依赖的带指纹资源。

若发布后验收失败，使用 `ops/rollback-server.sh <旧release目录名>`，遵循服务器现有配置，只切换 `current`，不删除旧版本或直接修改线上文件。完成后向用户报告发布 SHA、release、验收结果和是否发生回滚。
