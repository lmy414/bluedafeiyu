# 作品类型

每张公开作品只能选择一个类型。`categoryIds` 保留数组结构，长度固定为 1；角色、Tag、专题分别沿用原来的字段。类型描述在 `data/categories.json`，审核和重分类的详细规则在 `admin/src/lib/work-types.mjs`。

| 类型 | id | 判断边界 |
| --- | --- | --- |
| 梗图 | `meme` | 单幅画面，主要表达明确的梗、吐槽、态度或聊天反应。一幅画面中有多个角色不等于多格漫画。普通人物姿态不自动算梗图。 |
| 插画 | `illustration` | 人物、场景、氛围和艺术构图，含普通头像和半身像。 |
| 漫画 | `comic` | 至少两个明确分格或分镜，可表达对白、动作、反应、对比、不同角色或并列笑点。不要求叙事、时间顺序或情节推进。三视图、结构拆解、表情素材合集和普通拼贴不自动算漫画。 |
| 立绘 | `standing` | 白底、透明底或简单纯色下的独立人物，一般全身或接近全身，无完整场景构图。 |
| 设定图 | `setting` | 有明确的设计参考信息：三视图，或完整立绘配结构拆解、配件细节、色板、部位标注等。普通白底人物归立绘。 |
| 其他 | `other` | 形式特殊、信息不足或看不清，无法可靠归入前五类。 |

判断顺序为漫画、设定图、梗图、立绘、插画、其他。《那你们很棒棒哦？2》的上下反应分镜和《天下第一学院（？）》的多格角色对比均归漫画。GIF 动画帧的数量不算分镜。每张类型数量相加等于作品总数。

站内和 GitHub 投稿表单要求投稿者选择一个类型，入队字段为 `fields.categoryId`。所选类型作为审核参考，最终以画面规则为准。旧 GitHub 投稿和 QQ 投稿仍可不带这个字段；QQ 群内的命令和采集行为沿用现有规则。

后台作品编辑、人工收录和批量修改均为单选。Works 字段校验、审核结果校验和站点快照构建均会拒绝空类型或多个类型。原始投稿和历史审核记录保留。

## 存量重分类

2026-10-07 对 746 张公开作品使用 PI Agent 配置的 `cpa / deepseek/deepseek-v4.1-flash` 看图分类，并逐张复核漫画、立绘、设定图、其他类及低置信度图片，结合人工看图纠正边界案例。结果及逐图理由保存在 `reports/2026-10-07-classification.json`；模型调用记录、原始图片摘要和原数据备份放在不提交的 `.build/classification-20261007-v2/`。

```powershell
node tools/classification/reclassify.mjs --content-dir <内容仓路径> --run-dir .build/<新的运行目录>
node tools/classification/recheck.mjs .build/<新的运行目录>
node tools/classification/apply.mjs .build/<新的运行目录>
node tools/build_site.mjs --content-dir <内容仓路径> --out .build/type-preview
node tools/classification/review-page.mjs .build/type-preview
node tools/preview_site.mjs --dir .build/type-preview --port 5177
```

重分类从当前站点快照读取作品并附本地图片，保留 id、slug、原图路径、署名、来源、授权和状态。修改分类规则后应使用新的运行目录，避免复用旧规则下的结果。PI CLI 路径可通过 `PI_CLI` 指定；工具读取 PI 已有的模型和凭据配置，不记录密钥。

本次只改变类型，作品正文和语言译文未改写；已有译文的 `sourceHash` 在原摘要匹配时同步到新的类型摘要。已隐藏或移除的记录继续保留原状态，其中一条缺失图片的多类型历史记录收敛为其他。

## 后台类型同步

生产后台沿用 GitHub Actions 的 Linux standalone 发布包。类型迁移前确认没有发布批次运行，再执行下列命令。预演只读取数据库；实际执行先备份 SQLite，再在同一事务内同步六类描述和作品类型。

```bash
python3 tools/classification/sync-admin.py --database <后台数据库绝对路径>
python3 tools/classification/sync-admin.py --database <后台数据库绝对路径> --apply
```

同步工具保留作品 ID、slug、正文、来源、授权、署名、创建与更新时间、隐藏状态和待发布标记。标题或 slug 与复核报告不一致时停止，避免覆盖后台的新编辑。历史原始数据中的类型及已有译文摘要同步更新，备份保存在数据库旁的 backups 目录。
