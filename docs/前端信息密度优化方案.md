## 2. 方案原则

1. **标准化，不打补丁**：全部密度值收进 `CardDensity.css`（v2 重写；它本就是密度层、加载序在 `demo-design.css` 皮肤之后）。不改页面模板、不加页面级样式。
2. **只动几何，不动视觉**：颜色、字体族、圆角风格、深浅主题、移动端（<760px 维持现状）不变。
3. **不改任何公开 URL 与 DOM 骨架**，唯一例外是选配的主页「最新作品直达区」。
4. **区分页面性质**：目录/图库页重拳提密度；关于/更新日志等长文阅读页只收页头与共享组件，**不动正文行宽与行距**（阅读效率优先于密度）；活动页主视觉卡保留。
5. 选择器带 `body.archive.refined` / `body.archive` 前缀压过皮肤层；旧目录页用构建产物已有的 `data-legacy-category` body 属性作用域，无需改模板。不引入 `!important`（角色卡图高沿用现有惯例）。

## 3. 分项设计与实测对照（1440 宽，整页高 scrollHeight）

### A. 主页 `/`

| 区块 | 现状 | 目标 | 手段 |
| --- | --- | --- | --- |
| 顶栏 | 70px | 59px | min-height 0 + padding 8/28 |
| Hero | 297px（h1 48px） | 170px（h1 25px） | padding 48/42→14/12；统计块 dd 27→18px |
| 大入口卡 ×2 | 215px | 108px | padding 13/16；h2 17px；图条 72px；视频图容器 min(40%,150px) |
| 次级入口 ×3 | 62px | 44px | padding 11/14；h2 14px |
| 专题精选滑块 | 210px | 176px | copy padding 13/18；h2 19px；拍立得 108×100 |
| **最新作品直达区（选配）** | 无 | **444px，12 件可点作品** | 图区定高 150 + `object-fit:contain` 软底（同角色卡既有模式，**作品完整显示不裁剪**） |

- 原型局限：语言切换、自定义下拉、滑块、表单增强脚本被剥离——submit/search 等页的「原版」比线上偏高（区块未折叠），对比时以同 DOM 口径为准；不影响几何评估。

## 6. 验收方式

1. 数字断言（1440 宽）：主页首屏 ≥12 件可点作品、hero ≤180px、入口卡 ≤120px；browse/videos 6 列；characters/category 5 列；各页整页高不超过上表「紧凑」值的 +3%。headless Chrome 截图对照入档。
2. `npm --prefix frontend run check:components` 通过；`npm run test:frontend` 通过；增量构建成功。
3. 三语（zh/en/ja）× 深色 × 375/760px 抽查：无溢出无截断（重点：en 长标题在入口卡 17px 与 category 卡 15px 下的表现）。
4. 发布前检查 loop6 磁盘余量，走既有 Hermes 管线。

## 7. 风险与坑

- 特异性：皮肤层是 `body.archive.refined X`，覆盖层必须同前缀靠加载序取胜（已实测验证）；`data-legacy-category` 是构建产物既有属性，作 CSS 钩子无需改模板。
- 列数增加使首屏图片请求数上升（CDN 无碍，弱网首屏字节略增）。
- 视频 portal 卡绝对定位艺术图依赖卡高下限 ~112px（108px 实测贴合）；创作者导览图改高度后保持 `width:auto` 防拉伸。
- 阅读页（about/changelog）刻意轻改——若站长希望更紧，另行讨论行距/行宽口径。
